coc-agent

A local system that plays Clash of Clans on your iPhone through iPhone Mirroring. It banks loot so a freed builder can start right away, upgrades walls on their own track, does most of its work at night and while you're idle, and rewrites its own strategy as it learns.

Quick start

# 1. install (from the repo checkout) - copies the app to ~/.coc-agent and configures Claude Code
./bin/cocctl install

# 2. close any other Claude Code session that used computer use (it holds a lock), then check
cocctl doctor

# 3. watch one supervised run in your terminal (hands off the mouse)
cocctl run-now --attach

# 4. keep it running in the background                 # stop it any time
cocctl start                                          cocctl stop
cocctl status        # next run + why, base timers, recent runs
cocctl logs -f       # live scheduler log

cocctl presence      # what the Mac senses: home network, iPhone nearby, idle, night
cocctl strategy      # the agent's current living strategy
cocctl stats         # loot/attack, walls/day, "builder waited for loot" count

# optional: survive reboots / logins via launchd
cocctl autostart on                                   cocctl autostart off

Architecture

Two layers with a strict split. A dumb, reliable scheduler decides only whether a run may start now. A smart Claude Code agent decides everything about the game, including when the next run should happen.

Why expect instead of claude -p?

Claude Code's computer use only works in an interactive session. I checked: in claude -p the mcp__computer-use__* tools don't exist. So each run starts the real TUI inside a pseudo-terminal, and run_session.exp plays the human. It answers the folder-trust prompt and the per-session "Allow for this session" app-access prompt. It ends the session the moment the agent writes its result. App access also resets each session, which is why it has to be answered on every run.

The first run of each day (after 04:00) also does a daily review. It reads 3 days of stats and the learned availability, then rewrites strategy.md.

Timing: night-first, idle-aware

🌙 Night window 00:30–08:30

Prime time: you're asleep, so the Mac and phone are free. The scheduler holds caffeinate during the window so the Mac doesn't sleep or lock. The agent farms run after run until storages hit target, and leaves the longest jobs running before morning.

🏠 Presence sensing local only

Home = your router's hardware (MAC) address (auto-detected at install, or cocctl home-here). macOS hides the Wi-Fi name, the router address doesn't need it. iPhone nearby = Bluetooth sees your iPhone. Idle = no keyboard or mouse input. Sampled every 5 min into logs/presence.jsonl.

✨ Golden moments

Each run, the agent can say "an early run is worth it after 14:20, because the army is ready and storages are at 70%". If you're then home, the iPhone is nearby and you've been off the Mac 20+ min, the scheduler starts a run early.

Agent decides game-aware

  • Wake when a builder or the lab frees up, if the system can likely run then (from learned availability).
  • If that's during a busy daytime hour, wake at the next likely-free time and set "run early if idle".
  • Storages below target → wake when the army is ready (repeatedly at night).
  • Start long upgrades in the evening/night so they finish when the system can act.

coc at turns game timers into clock times. coc suggest-wake shows each candidate time and how often runs worked at that hour.

Strategy (your direction, the agent's details)

🏦 Bank, don't drain

Keep gold, elixir and DE near full (storage_target_fill, start 90%). The moment a builder or the lab frees up, the money is already there, so the next job starts that run. Farm the bank back up afterwards. North-star metric: "idle builder had to wait for loot" = 0.

🧱 Walls: their own track

A few segments every day (start: 6/day, 3/run), paid only from the surplus above the reserve. The reserve covers builder jobs due in the next 12 h. When a storage is about to overflow, extra goes into walls. Unknowns (does a wall need an idle builder? row upgrades?) get verified in game and recorded in walls.md.

⚔️ Farming

Loot, not trophies. Start: zap-dragon, take bases with ≥1M gold+elixir, or high DE when that's the gap. Don't farm a resource that's already full. Every attack is logged with its strategy name, so different approaches can be compared.

Learning loop: it evolves, it isn't scripted

Safety rails

Enforced by code

  • PreToolUse hook blocks request_access / open_application for any app but iPhone Mirroring. That's what makes auto-approving the access prompt safe.
  • --permission-mode dontAsk plus an allow-list: computer use, read anything, edit only memory/**, Bash only for ./bin/coc. No web.
  • Hard run cap (40 min), stall detection (5 min of silence → one nudge → stop), one run at a time, daily cap.
  • The parent Claude session's environment is never leaked into runs.

Enforced by instructions (the model must follow them)

  • Never tap anything with a real-money price. Close offers. (iOS also asks for authentication before a purchase.)
  • No gem spending unless "use_gems": true.
  • No settings, account, clan or chat actions.
  • On anything unexpected → finish with needs_human, which sends a Mac notification.

Limits & risks (read these)

Account risk

Supercell's Terms of Service ban bots and automation. Accounts can be suspended or banned. Since this goes through the real phone UI it looks like a human, but the ToS doesn't care how it's done. Use it only on an account you're prepared to lose.

The Mac must be awake, unlocked & plugged in at night

Computer use can't act on a locked screen. The scheduler's caffeinate stops sleep and auto-lock during the night window, but only if the Mac is unlocked when the window starts. Leave it open, plugged in, with the brightness down. The battery guard skips runs below 20% unplugged. Leaving the Mac unlocked overnight is a physical-security trade-off.

macOS permissions

Screen Recording and Accessibility belong to the app that launches Claude. With cocctl start from a terminal that already ran computer use, it inherits that grant. With autostart, macOS may ask again for python3. The run then ends with needs_human until you grant it.

Usage cost

One manual attack used ~2.0M input-side tokens (mostly cache reads) and ~9.5k output tokens over 27 requests. A full run with upgrades and 1 to 3 attacks will be roughly 1 to 4× that. On a Claude subscription that's plan usage, not dollars. Lower it with max_attacks_per_run, a cheaper model, or a higher min_interval_minutes.

One computer-use session at a time

Any other Claude Code session that used computer use holds the lock until it exits. The scheduler waits (+15 min) instead of failing. cocctl doctor shows who holds it.

Verified on 2026-11-13

The first real run worked end to end. The driver picked Allow on the access prompt (Down, Enter), the agent opened CoC through iPhone Mirroring, started a Blacksmith upgrade, did 2 farming attacks (+737k gold, +1.14M elixir), filled in base.json, and scheduled its own next runs.
